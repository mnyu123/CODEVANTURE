# 초기 아키텍처

## 실행 구성

```text
브라우저
  React: 웹 UI와 코딩 패널
  Phaser: 직접 이동, 충돌, 카메라, 월드 연출
  게임 진행 관리자: 사건, 분기, 보상, 저장할 상태
  코드 실행 Worker: 제한된 실행 환경과 결과 반환
        |
        | HTTPS (실제 연동은 후속 작업)
        v
Netlify Functions (Node.js / TypeScript)
  인증 확인, AI 사용량 제한, 입력·응답 검증
  AI 서비스 -> Gemini API
  저장 서비스 -> Supabase PostgreSQL
  로그인 -> Supabase Auth
```

현재 실행되는 것은 React 확인 화면과 `GET /api/health`뿐입니다.
SDK 설치를 실제 외부 서비스 연결 완료로 간주하지 않습니다.

## 코드 배치

- `src/`: 브라우저에 포함될 수 있는 코드
- `server/`: 서버 전용 코드. 브라우저에서 import하지 않음
- `netlify/functions/`: 서버 API 진입점
- `src/content/`: 버전 관리되는 게임 콘텐츠
- `src/runner/`: 제한된 코드 실행을 위한 브라우저 코드

초기 함수는 적은 수의 진입점으로 관리합니다. Fastify 같은 독립 HTTP 서버는 현재 구성에 포함하지 않습니다.

## 상태 소유권

Phaser와 React는 사건 단위로 통신합니다. 게임 진행 관리자가 최종 상태 변경을 결정합니다.
사용자 코드와 AI가 직접 문을 열거나 보상을 지급하지 못하게 합니다.

예정 흐름: 시작 대기 → 월드 등장 → 탐험 → 대화/코딩 → 실행 → 결과 연출 → 탐험.
코딩 중에는 탐험 입력을 차단하고, 복귀 시 눌린 키 상태를 초기화합니다.

## 실행과 외부 연결 경계

- 코드 입력과 코드 실행은 서로 다른 기능입니다.
- Worker만으로 보안 격리나 강제 메모리 한도가 완성되지 않습니다.
- 사용자 코드를 페이지 또는 Netlify 함수에서 직접 실행하지 않습니다.
- 초기 클라이언트 판정은 순위·경쟁의 권위 있는 검증이 아닙니다.
- 서버 채점이 필요해지면 별도 격리 실행 서비스를 설계합니다.
- AI 출력도 동일한 실행·테스트 과정을 통과해야 합니다.
- API 키는 서버에만 두고 브라우저 응답, 로그, 오류에 노출하지 않습니다.
- 인증과 RLS/소유자 검증을 붙이기 전에는 사용자 저장 기능을 공개하지 않습니다.

## 안정성 원칙

| 항목        | 구현 시 처리                                                       |
| ----------- | ------------------------------------------------------------------ |
| 실행 멈춤   | 실행 시간·연산량 제한, 취소 시 Worker 종료                         |
| 메모리      | 로그·출력 크기 제한, 장면 종료 시 리스너·타이머·게임 인스턴스 해제 |
| 오래된 결과 | 문제 ID·실행 ID를 확인해 화면 전환 전 요청 결과 무시               |
| 연결        | HTTP Data API 우선, 직접 DB 연결 시 서버리스용 풀 사용             |
| AI 지연     | 플랫폼 제한보다 짧은 요청 timeout, 중복 호출 차단, 유한 재시도     |
| 사용량      | 사용자별·전체 한도를 DB에서 원자적으로 관리                        |
| 저장        | 체크포인트 단위 저장, 저장 포맷 버전 관리                          |
| 실패 복구   | AI 장애·한도 초과를 표시하고 검증된 대체 해법 여부 결정            |

## 이후 외부 연결 순서

1. 첫 장면과 직접 이동을 로컬에서 구현합니다.
2. 한 개 문제의 제한된 실행과 판정을 검증합니다.
3. Supabase 로그인·RLS·저장 스키마를 구현합니다.
4. 서버에서 Gemini 코드 생성과 사용량 제한을 구현합니다.
5. 실제 계정의 요금제·한도를 확인한 뒤 Netlify에 배포합니다.
